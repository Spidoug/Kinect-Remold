# Kinect Remold — Xbox 360 — Linux

### Native Linux runtime for models 1414, 1473 and Kinect for Windows 1517

**by Douglas Santana - @spidoug**


Build from the repository root with `./Kinect-Remold.sh`. The build stage resolves dependencies, firmware and the kernel-specific virtual-camera module, then publishes the complete native runtime to `binaries/linux/drivers/kinect-xbox-360-remold/`. The generated `INSTALL.sh` performs only offline installation of that prepared bundle.

The generated driver bundle uses `bin/`, `libexec/kinect360-remold/` and `support/`; installation maps those files into the normal system `/usr` and `/etc` locations.

The runtime uses per-Kinect camera, audio, audio-control and virtual-camera endpoints keyed by stable physical `deviceId`. The resident Broker owns both `control.sock` and `sdk.sock` in the configured runtime directory (`$REMOLD_RUNDIR/kinect360-remold`, `/run/kinect360-remold` by default).

No package-manager package is generated by this repository.

## Hardware model routing

The runtime has separate hardware profiles:

- **Kinect 1414:** camera `045E:02AE` with `bcdDevice 0x010B`; motor/LED/accelerometer use dedicated `045E:02B0`. Runtime `02BB/02C3` is audio only for motor classification.
- **Kinect 1473:** camera `045E:02AE` with newer `bcdDevice` (known Xbox value `0x0205`); `045E:02C2` remains an untouched parent hub; motor/LED/accelerometer use the 02BB/02C3 `MI_00` bulk control interface. After the UAC firmware upload the microphones are captured through `snd-usb-audio` / ALSA like 1414 and 1517; no kernel driver is detached, so the control broker is never disturbed, and udev marks the sound device `ACP_IGNORE`/`PULSE_IGNORE` so desktop sound servers do not open it.
- **Kinect for Windows 1517:** camera `045E:02BF`; dedicated `045E:02C2` motor/LED/accelerometer control uses the classic first-generation protocol; factory `045E:02BE` USB Audio is captured through ALSA without the 02AD firmware transition. The product stream is then republished through the same `KinectRemold` system capture card used by 1414/1473.
- **Common LED behavior:** `off`, `green`, `red`, `blink-green`. Camera/control preparation initializes supported first-generation models to solid green once per fresh physical session.

Do not use an audio PID alone to decide the model; model selection is anchored to the camera descriptor and physical USB identity.

The Linux audio contract intentionally has two consumers of one product-owned capture session: the internal per-device Remold socket used by Studio/SDK and a normal ALSA capture endpoint for the operating system. `snd-aloop` provides the `KinectRemold` card; AudioBridge writes each Kinect to a deterministic playback substream and ordinary Linux applications record the paired capture substream. This preserves the Windows behavior where installing the driver leaves a microphone endpoint available to the operating system without allowing desktop audio clients to take ownership of the physical Kinect USB audio function.


### Runtime disconnect timing

Runtime loss of the physical Kinect is bounded to approximately 3 seconds. Camera/depth watchdogs trigger within 2.5–3.0 seconds, device-presence grace is 3 seconds, and device I/O used for runtime liveness is capped at 3 seconds. Reconnect discovery runs independently and begins immediately after the loss is published.
